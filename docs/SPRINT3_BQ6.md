# Sprint 3 / S3-10: usage events and BQ6 (monthly feature adoption)

**BQ6 (Type 3):** "Which core CampusMeal features are used fewer than two times per month by at least 80% of monthly active users?"

Two endpoints, both under `/api/v1/`:

| Endpoint | Role | Purpose |
|---|---|---|
| `POST analytics/usage-events` | any authenticated user | Idempotent ingestion of `SESSION_STARTED` / `FEATURE_USED` events (Android outbox, iOS) |
| `GET analytics/feature-adoption?month=YYYY-MM` | `ANALYST` | BQ6 report. `USER` gets 403 |

BQ8 (`POST analytics/events`, `GET analytics/explanation-selection`) is unchanged.

## 1. `POST analytics/usage-events`

Returns **202** with an empty body. Idempotent per account: the unique index is `(user_id, client_event_id)`, so a retry or an outbox replay with the same `clientEventId` returns 202 again and is stored once. The user comes from the access token, never from the body.

```json
{
  "clientEventId": "9b2c7a4e-5d1f-4c8a-8e0b-3a6f1d2c4b55",
  "eventType": "FEATURE_USED",
  "feature": "MEAL_COMPARISON",
  "platform": "ANDROID",
  "occurredAt": "2026-10-27T15:04:05Z"
}
```

| Field | Rule |
|---|---|
| `clientEventId` | UUID generated by the client; keep it identical on every retry |
| `eventType` | `SESSION_STARTED` or `FEATURE_USED` |
| `feature` | **Required** for `FEATURE_USED`: `INVENTORY`, `RECIPES`, `RESTAURANT_SEARCH`, `RESTAURANT_DETAIL`, `MEAL_COMPARISON`. **Must be null/omitted** for `SESSION_STARTED` |
| `platform` | `ANDROID` or `IOS` |
| `occurredAt` | ISO-8601 UTC ending in `Z`. Not in the future (5 min skew allowed) and not older than 90 days |
| `zoneId`, `foodCategory`, `budgetBand` | Optional coarse demand context for BQ9 (`zoneId` <= 64 chars, `foodCategory` <= 40 chars, `budgetBand` LOW / MEDIUM / HIGH). Never coordinates |

Unknown fields (e.g. `latitude`) are rejected with 400 by the global whitelist. Android: do not give request properties default values (`encodeDefaults = false` would drop them).

| Status | When |
|---|---|
| 202 | Accepted (new or duplicate) |
| 400 `VALIDATION_ERROR` | Missing/invalid field, `feature` on `SESSION_STARTED`, `FEATURE_USED` without feature, `occurredAt` out of range, unknown field |
| 401 | Missing/invalid access token |

What counts as a use: one explicit user interaction (open inventory, search restaurants, open a detail, run a comparison...). Recompositions, retries and opening the internal ANALYST report do **not** count.

The event's month is decided by `occurredAt` (Bogotá), not by when it arrives, so events synced late are attributed to when they happened.

## 2. `GET analytics/feature-adoption?month=2026-09`

Definitions (month = calendar month in `America/Bogota`):

- **MAU**: distinct accounts with at least one usage event whose `occurredAt` falls in the month.
- **Low-use user** for a feature: a MAU with **fewer than 2** `FEATURE_USED` events of that feature, **zero uses included**.
- `lowUseRate = lowUseUsers / MAU` (4 decimals). `flagged = lowUseRate >= 0.80` (compared as `lowUseUsers * 5 >= MAU * 4`, so 8/10 is exactly flagged).
- No MAU in the month: `status = NO_DATA`, empty `results`, no division by zero.
- `partialMonth` is true while the requested month is the current month in Bogotá. `includesSyntheticData` is true when some counted events come from the demo seed.

```json
{
  "month": "2026-09",
  "status": "OK",
  "monthlyActiveUsers": 10,
  "threshold": 0.8,
  "lowUseBelowUses": 2,
  "partialMonth": false,
  "eventsReceived": 62,
  "includesSyntheticData": true,
  "generatedAt": "2026-10-27T00:30:20.780Z",
  "results": [
    { "feature": "RECIPES", "lowUseUsers": 10, "lowUseRate": 1, "flagged": true },
    { "feature": "MEAL_COMPARISON", "lowUseUsers": 8, "lowUseRate": 0.8, "flagged": true },
    { "feature": "INVENTORY", "lowUseUsers": 7, "lowUseRate": 0.7, "flagged": false },
    { "feature": "RESTAURANT_DETAIL", "lowUseUsers": 5, "lowUseRate": 0.5, "flagged": false },
    { "feature": "RESTAURANT_SEARCH", "lowUseUsers": 0, "lowUseRate": 0, "flagged": false }
  ]
}
```

`results` is ordered by `lowUseRate` descending, then feature name.

| Status | When |
|---|---|
| 200 | Always for a valid month (check `status`) |
| 400 `VALIDATION_ERROR` | `month` not `YYYY-MM` (e.g. `2026-13`) |
| 401 / 403 | No token / not an `ANALYST` |

## 3. Data model and migration

Migration `1790520000000-CreateUsageEvents` creates table `usage_events` with enums `usage_event_type`, `usage_feature`, `usage_budget_band` (reuses `client_platform`). Constraints: `UQ_usage_events_user_client_event (user_id, client_event_id)`, `CHK_usage_events_feature_for_type`, FK to `users` with `ON DELETE CASCADE`. The `synthetic` flag marks demo rows; real clients cannot set it.

## 4. Demo data

```bash
npm run migration:run
npm run seed:auth
npm run seed:usage        # 10 inactive demo accounts + 62 synthetic events
```

The seed uses the **previous calendar month** in Bogotá (override with `USAGE_SEED_MONTH=YYYY-MM`). Expected report for that month: `MEAL_COMPARISON` 8/10 = 80% flagged, `INVENTORY` 7/10 = 70% not flagged, `RECIPES` 10/10 = 100% flagged (users with zero uses count), `RESTAURANT_DETAIL` 50%, `RESTAURANT_SEARCH` 0%. The seed is idempotent. Demo accounts are `usage-demo-NN@campusmeal.local`, inactive, with random passwords.

## 5. Verification done (local, 2026-10-26)

`npm run build`, `npm run lint`, `migration:run`, `seed:auth`, `seed:usage`, then with curl as `demo` (USER) and `analyst`: POST 202; same UUID again 202 and exactly one row; 400 for `SESSION_STARTED` with feature, `FEATURE_USED` without feature, future `occurredAt`, `occurredAt` older than 90 days and an extra `latitude` field; 401 without token; GET as USER 403; `month=2026-13` 400; `2026-09` returns the table above; `2025-01` returns `NO_DATA`; the current month returns `partialMonth: true`. Midnight / month-boundary behaviour relies on `to_char(occurred_at AT TIME ZONE 'America/Bogota', 'YYYY-MM')` and was not exercised with boundary data.
